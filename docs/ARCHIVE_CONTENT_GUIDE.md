# ARCHIVE 콘텐츠 관리 가이드

아카이브 글은 **Markdown 파일 하나가 상세 페이지 하나**입니다. 화면을 만드는 React·JSX 파일은 수정하지 않아도 됩니다.

## 어디를 수정하나요?

| 변경할 내용 | 파일 또는 폴더 |
| --- | --- |
| 프로그램명·부제·진행 기간·활성화 여부 | `content/archive/programs.json` |
| 회차별 제목·날짜·장소·태그·본문 | `content/archive/*.md` |
| 새 글 복사용 템플릿 | `content/archive/_template.md` |
| 업로드할 이미지 | `public/images/archive/` |

현재 회차 파일은 Figma 시안의 문구와 임시 콘텐츠로 구성했습니다. `더미더미`, `000`, 긴 제목 테스트 문구 등은 최종 원고로 교체해 주세요. INTRO 문구도 게시 전 검토해 주세요. 회색 이미지는 모두 교체용입니다.

PC·모바일 시안에 회차 태그와 나열 순서가 서로 다른 부분이 있어, 실제 사이트는 **동일한 파일의 `badge`와 `order`를 PC·모바일·사이드 목록에서 함께 사용**합니다. 현재는 INTRO → DAY 1 → DAY 2 → DAY 3 순서입니다.

## 1. 기존 글 수정

예를 들어 첫날의 글은 다음 파일입니다.

`content/archive/01-new-perspective.md`

파일 상단의 두 `---` 사이가 글의 기본 정보이고, 두 번째 `---` 아래가 본문입니다.

```md
---
id: "meetup-001"
slug: "new-perspective"
program: "meetup"
order: 10
badge: "DAY 1"
title: "국악의 현실 너머, 새로운 관점으로 바라보다"
date: "2026-08-31"
location: "국립국악원 예인마루"
---

![현장 사진 설명](/images/archive/meetup-001-01.jpg)

첫 번째 본문 문단입니다.

두 번째 본문 문단입니다.
```

따옴표 안의 문구와 본문을 바꾸고 저장하면 됩니다. 기본 정보는 한 항목에 한 줄로 작성하고, 따옴표를 닫아 주세요. 문구 안에 큰따옴표가 필요하면 `\"`로 입력하거나 작은따옴표를 사용하세요.

## 2. 새 회차 등록

1. `content/archive/_template.md` 내용을 복사합니다.
2. 같은 폴더에 `08-new-record.md` 같은 새 파일을 만듭니다. **파일명은 `_`로 시작하지 않아야 하고 확장자는 `.md`여야 합니다.**
3. `id`와 `slug`를 기존 글과 겹치지 않게 바꿉니다.
4. 프로그램·정렬 순서·태그·제목·날짜·장소를 입력합니다.
5. 본문과 이미지 경로를 입력합니다.
6. 공개할 준비가 되면 `published: false`를 **`published: true`**로 바꿉니다.
7. 파일을 커밋합니다. 별도로 목록이나 상세 페이지 코드를 추가할 필요가 없습니다.

예시:

```md
---
id: "meetup-008"
slug: "new-performance"
program: "meetup"
order: 80
badge: "DAY 4"
title: "새로운 공연을 만나다"
date: "2026-09-05"
location: "국립국악원 예인마루"
published: true
---

![첫 현장 사진](/images/archive/meetup-008-01.jpg)

현장의 이야기를 입력합니다.

## 관객과 만나는 시간

![두 번째 현장 사진](/images/archive/meetup-008-02.jpg)

다음 이야기를 입력합니다.
```

이 글은 목록에 자동 등록되고 `/archive/new-performance` 주소로 상세 페이지가 생깁니다. 직접 주소로 접속하거나 새로고침해도 표시됩니다.

작성 중인 글은 `published: false`로 두세요. `_template.md`는 항상 목록에서 제외되므로 그대로 보관해도 됩니다.

## 3. 각 항목의 의미

| 항목 | 입력 방법 |
| --- | --- |
| `id` | 내부 고유 이름. 영문 소문자·숫자·하이픈만 사용하며 중복 금지 |
| `slug` | 상세 주소의 마지막 부분. 영문 소문자·숫자·하이픈만 사용하며 중복 금지 |
| `program` | `programs.json`의 `id`. 현재 MEET UP은 `meetup` |
| `order` | 작은 숫자부터 먼저 표시. 따옴표 없는 숫자로 입력 |
| `badge` | `INTRO`, `DAY 1`, `DAY 2` 등 표시할 태그 |
| `title` | 목록과 상세 페이지에 함께 표시되는 제목 |
| `listTitle` | 선택 사항. 목록만 짧게 표시할 때 사용. 생략하면 `title` 사용 |
| `date` | `"2026-08-31"`처럼 실제 날짜를 `YYYY-MM-DD`로 입력 |
| `location` | 장소. 생략하면 장소 줄을 표시하지 않음 |
| `subtitle` | 선택 사항. 상세 제목 아래에 추가할 설명 |
| `published` | 작성 중이면 `false`, 공개하려면 `true`. 생략하면 공개 |

번호·태그는 `id`나 파일명으로 추정하지 않습니다. `badge`에 쓴 문구가 그대로 표시됩니다. INTRO는 흰 바탕·보라색 글자로 구분됩니다.

기존 글의 `slug`를 바꾸면 주소도 달라져 이전에 공유한 링크는 더 이상 열리지 않습니다. 기존 주소를 유지하려면 `slug`는 그대로 두세요.

## 4. 제목·DAY·날짜·장소 변경

기본 정보에서 해당 줄을 수정합니다.

```yaml
title: "새로운 제목"
badge: "DAY 2"
date: "2026-09-02"
location: "새로운 진행 장소"
```

목록·PC 사이드 목록·모바일 목록·상세 화면은 같은 글을 사용하므로 따로 수정할 필요가 없습니다. `listTitle`을 입력했다면 목록 제목을 바꾸려는 경우 그 항목도 확인하세요.

## 5. 본문·서브 제목·이미지 자유롭게 추가

- `## 서브 제목`으로 새로운 구간을 만듭니다.
- 문단 사이에 빈 줄을 한 줄 넣습니다. 문장 안의 단순 줄바꿈은 이어진 문장으로 표시됩니다.
- `**강조할 문구**`는 굵게 표시됩니다.
- `[링크 이름](https://example.com)`으로 링크를 만듭니다.
- 이미지 줄 뒤에 관련 문단을 작성합니다. PC에서는 이미지와 문단이 나란히, 모바일에서는 이미지 다음에 문단이 표시됩니다.
- 이미지가 없는 문단·여러 문단·연속 이미지·여러 서브 제목도 사용할 수 있습니다.

```md
## 새로운 서브 제목

![사진에 담긴 내용 설명](/images/archive/meetup-001-02.jpg)

사진과 관련된 첫 번째 문단입니다.

사진과 관련된 두 번째 문단입니다.

![다음 사진 설명](/images/archive/meetup-001-03.jpg "필요한 경우 사진 캡션")

다음 사진에 대한 본문입니다.
```

이미지는 위 예시처럼 별도 줄에 작성하세요. HTML·JSX·스크립트를 넣을 필요가 없으며, 입력해도 코드로 실행하지 않습니다.

## 6. 이미지 업로드·교체

1. 이미지를 `public/images/archive/`에 업로드합니다. 폴더를 회차별로 나눠도 됩니다.
2. 파일명은 `meetup-001-01.jpg`처럼 영문·숫자·하이픈으로 작성하세요. 파일명과 확장자의 대소문자도 정확히 일치해야 합니다.
3. Markdown에서는 **`public`을 제외한 주소**를 사용합니다.

저장 위치: `public/images/archive/meetup-001-01.jpg`

본문 입력:

```md
![참여자들이 둘러앉아 이야기하는 현장](/images/archive/meetup-001-01.jpg)
```

JPG·PNG·WebP·GIF·AVIF·SVG를 지원합니다. 사진은 가로형 16:9를 권장합니다. 이미지 영역은 시안의 16:9 비율을 유지하며, 다른 비율의 사진은 찌그러지거나 잘리지 않도록 영역 안에 맞춰 표시합니다.

파일이 없거나 경로가 올바르지 않으면 회색 플레이스홀더가 표시됩니다. 실제 파일을 업로드하고 올바른 경로로 다시 커밋하면 교체됩니다. 배포 전에 미리보기에서 회색 이미지가 남아 있지 않은지 확인하세요.

## 7. 순서 변경

`order`만 수정합니다. 숫자가 작을수록 위에 표시됩니다.

```yaml
order: 15
```

현재 10, 20 순서인 글 사이에 넣으려면 15로 입력합니다. 같은 숫자가 있다면 주소 이름(`slug`) 순서로 정렬됩니다. 파일명이나 날짜만 변경해서는 순서가 바뀌지 않습니다.

## 8. 프로그램 정보와 향후 BOOT CAMP 활성화

`content/archive/programs.json`에서 관리합니다.

```json
{
  "id": "bootcamp",
  "label": "BOOT CAMP",
  "title": "프로그램 제목",
  "subtitle": "필요하면 추가할 부제",
  "period": "2026. 10.1-10.3",
  "enabled": false
}
```

**현재 BOOT CAMP는 반드시 `false`로 유지합니다.** 클릭·키보드 실행이 되지 않으며, 해당 프로그램의 글도 공개되지 않습니다.

향후 운영이 결정되면:

1. `program: "bootcamp"`인 Markdown 글을 준비합니다.
2. 프로그램 제목·진행 기간을 수정합니다.
3. BOOT CAMP의 `enabled`를 `true`로 바꿉니다.
4. 커밋 후 미리보기에서 확인합니다.

메뉴는 `/archive?program=bootcamp`로 연결되며 새 컴포넌트는 필요 없습니다. 공개된 글이 없어도 빈 목록 안내로 표시됩니다. 프로그램 `id`는 글의 `program`과 연결되어 있으므로 임의로 바꾸지 마세요.

## 9. GitHub에서 수정·등록하기

1. 저장소에서 작업할 브랜치를 선택합니다. 이번 작업 브랜치는 `feature/archive-pages`입니다.
2. 기존 글은 해당 `.md` 파일을 열고 연필 버튼으로 수정합니다.
3. 새 글은 `content/archive/`에서 **Add file → Create new file**로 만듭니다.
4. 이미지는 `public/images/archive/`에서 **Add file → Upload files**로 올립니다.
5. 수정 내용을 확인하고 **Commit changes**를 누릅니다.
6. Vercel의 해당 브랜치 미리보기에서 목록·상세·모바일을 확인합니다.

사진과 본문을 여러 번에 나누어 올릴 때는 먼저 이미지를 업로드하거나, 글을 `published: false`로 작성한 뒤 마지막에 공개하세요.

## 10. 사이트 반영

GitHub 연동 자동 배포가 활성화된 Vercel 프로젝트에서는 브랜치에 커밋·푸시하면 새 미리보기 배포가 만들어집니다. 기존에 열어둔 미리보기를 새로고침하고 최신 커밋의 배포가 완료되었는지 확인하세요.

정식 사이트 반영은 검토한 작업을 운영 브랜치(`main`)에 병합한 뒤 진행합니다. **이번 구현 작업은 작업 브랜치에만 푸시하며 `main`에 병합하지 않습니다.**

기본 정보가 잘못되면 새 배포가 실패하고 이전 정상 배포가 유지됩니다. Vercel의 빌드 로그에 나온 파일명과 항목을 수정한 뒤 다시 커밋하세요.

## 11. 게시 전 확인

- 제목·DAY·날짜·장소·순서가 맞는지 확인합니다.
- 모든 `id`와 `slug`가 고유한지 확인합니다.
- 임시 문구·회색 이미지가 남았는지 확인합니다.
- 사진 설명(대체 텍스트)이 각 사진에 맞는지 확인합니다.
- PC·모바일에서 목록과 상세를 각각 확인합니다.
- 직접 상세 주소로 접속하고 새로고침해 봅니다.
- BOOT CAMP가 여전히 비활성화되어 있는지 확인합니다.

개발 환경에서 검사할 때는 다음 명령을 사용합니다.

```sh
npm run test:archive
npm run lint
npm run build
```

잘못된 날짜·중복 주소·없는 프로그램·필수 항목 누락은 배포 전에 파일명을 포함한 오류로 안내됩니다. 오류를 피하려고 화면 코드나 자동 검사를 수정하지 말고 해당 콘텐츠 파일의 내용을 고쳐 주세요.
